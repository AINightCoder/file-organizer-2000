## 核心设计理念

### 1. 向后兼容
- 所有新功能通过 `enableKnowledgeManagement` 总开关控制
- 默认关闭，不影响现有用户
- 可以独立启用/禁用各个子功能

### 2. 递归处理架构
```
旧架构：Inbox → 线性13步 → 完成

新架构：Inbox → 判断是否需要拆分
                ├─ 不拆分 → 线性处理 → 完成
                └─ 拆分 → 原子化拆分 → 删除原笔记 → 递归处理每个子笔记
```

### 3. 两级拆分机制
1. **知识点原子化拆分**（主要）
   - 基于AI识别独立知识点
   - 每个笔记专注一个核心概念

2. **长度限制拆分**（辅助）
   - 单个笔记不超过 maxNoteLength（默认3000字）
   - 在段落边界智能分割

### 4. 错误容错
- 拆分失败不阻断流程
- 支持回滚机制
- 详细的日志记录

## 技术亮点

## 使用说明

### 启用知识管理功能

1. 打开插件设置
2. 找到"知识管理功能"区域
3. 启用 `启用知识管理功能` 开关
4. 配置相关参数：
   - `启用原子化拆分`: 是否进行知识点拆分
   - `笔记最大长度`: 单个笔记最大字符数（默认3000）
   - `笔记最小长度`: 低于此长度不拆分（默认100）
   - `拆分策略`: atomic/length/both

### 工作流程

1. 将笔记放入 Inbox 文件夹
2. 插件自动判断是否需要拆分
3. 如需拆分：
   - 按知识点拆分成多个原子笔记
   - 检查每个笔记长度，超长则继续拆分
   - 删除原笔记
   - 递归处理每个子笔记
4. 每个子笔记继续走完整的处理流程：
   - 文档分类
   - 文件夹推荐
   - 文件重命名
   - 内容格式化
   - 标签推荐

## 测试建议

### 基本测试用例

   - 创建一个简短、单一主题的笔记
   - 验证不会被拆分
   - 正常走完流程

2. **多知识点笔记**
   - 创建包含2-3个明显不同主题的笔记
   - 验证拆分为多个独立笔记
   - 验证原笔记被删除
   - 验证每个子笔记都被正确处理

3. **超长笔记**
   - 创建超过3000字的单一主题笔记
   - 验证按长度拆分
   - 验证片段保持连贯性

4. **短笔记**
   - 创建低于100字的笔记
   - 验证不触发拆分
   - 正常处理

5. **拆分失败场景**
   - 模拟AI服务失败
   - 验证继续按原笔记处理
   - 验证不影响后续流程

6. **附件笔记**
   - 创建带附件的笔记
   - 验证拆分后第一个笔记包含附件
   - 验证其他笔记不包含

## 性能考虑

### Token消耗
- 每次拆分需要调用AI服务2次（原子化+长度）
- 大笔记的token消耗较高
- 建议配置本地模型或控制并发

### 处理速度
- 递归处理会增加总体处理时间
- 但每个子笔记独立处理，不阻塞其他文件
- 队列机制保证并发控制

### 建议优化
- 设置合理的 minNoteLength 避免过度拆分
- 使用快速的AI模型
- 考虑异步队列优化
