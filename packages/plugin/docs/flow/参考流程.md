# Obsidian 知识库规则

## 知识库分类结构模板

- `1.Area/` - 不同知识领域的理论
  - AI/
  - Flutter/
  - Unity3d/
  - 编程/
  - 营销/
  - 自媒体/
  - 产品设计/
  - 产品运营/
  - [其他二级分类]/
    - `01.Roadmap/` - 路径规划, 知识点地图, 索引归档笔记双链
    - `02.What/` - 核心概念
    - `03.Why/` - 准则/原则/思想等, `道法术`里的 `道`
    - `04.How/` - 标准操作流程,最佳实现, 教程等, `道法术`里的 `法`
    - `05.Tool/` - 具体的工具, `道法术`里的 `术`
    - `06.Resource/` - 领域相关资源, 素材库
- `2.Project/` - 具体的项目实践. 基于 `1.Area` 的指导进行的具体实践记录和相关信息/资源/上下文等. 基于实践的结果要反过来增强或调整 `1.Area`中的内容
  - 健康管理/
  - VocalMind项目
  - 个人IP打造/
  - [其他二级分类]
    - `01.Plan/` 项目计划
    - `02.Do/` 具体任务拆分和执行
    - `03.Resource/` 项目专属, 一次性的资源
    - `04.Result/` 项目产出成果
    - `05.Log/` 会议记录, 项目执行记录
    - `06.Review/` 项目复盘, 经验总结
- `3.Archive/` - 项目归档, 存放完成的/放弃的/过时的项目

## 元数据模板

每个文件应包含以下YAML前言元数据：

```yaml
---
id: "{{date:YYYYMMDDHHmm}}-{{title}}"
title: "标题"
version: "1.0" // 每次修改都升级
create: 2025-10-01
update: 2025-10-02
source: "来源说明" // 可选，说明笔记来源，如：官方文档、个人经验、网络文章、书籍等
credibility: 5 // 可信度评级 1-10，1=低质量/不可信，5=一般，10=高质量/权威可信(1-3：低质量/不可信（如未验证的网络传言、过时信息等 4-6：一般质量（如普通网络文章、个人经验总结等 7-8：较高质量（如技术博客、实践验证过的方法等）9-10：高质量/权威可信（如官方文档、权威书籍、专业论文等)
cate: 二级目录
subcate: 三级目录
tags: ["tag1", "tag2", "tag3"]  // 3-6 个维度数, tag数不限制，如道/法/术/实践维度 技术栈维度 内容类型维度 工具类型维度 商业维度 项目阶段维度等, 优先使用知识库已有的tag
summary: "总结核心内容,包括该笔记的主要结论或要点说明,300字以内"
---
```

## Roadmap 生成提示词

```
我想系统性地学习【领域名称】，您是这个领域中拥有超过20年经验的顶尖专家和资深教育家。你不仅精通该领域的全部理论知识和前沿动态，更擅长将复杂庞大的知识体系，为不同阶段的学习者设计出清晰、高效、循序渐进的学习路径。请为我设计一个完整的学习路线图。

## 任务要求：
1. 将学习内容分为初级、中级、高级三个层次
2. 每个层次列出3-5个核心知识模块
3. 每个模块包含3-5个关键知识点
4. 提供学习时间估算和前置要求
5. 推荐1-2个该层次的优质学习资源

### 📚 初级（入门基础）
**学习目标**：[该阶段要达到的具体能力]
**预计时间**：[学习时间估算]
**前置要求**：[需要具备的基础知识]

#### 1.[模块名称]
- **知识点1：[具体知识点]**

- **知识点2：[具体知识点]**

- **知识点3：[具体知识点]**

#### 2.[模块名称]
- **知识点1：[具体知识点]**

- **知识点2：[具体知识点]**

[继续其他模块...]

#### 推荐资源：
- [资源1名称]：[简要说明]
- [资源2名称]：[简要说明]

### 🚀 中级（进阶提升）
[按相同格式展开]

### 🎓 高级（专业精通）
[按相同格式展开]

### 💡 学习建议
1. **学习顺序**：[建议的学习路径]

现在请生成具体的学习路线图。
```

## 笔记归档工作流

**示例**: 假如 `Inbox/flutter analyze设置.md` 是新创建的笔记

1. 拆分当前笔记, 把它按照单个知识点拆分成独立的原子化笔记文件, 同时单个笔记文件不能超过3000字, 如果超过了, 按文件名1/2/3拆分. 拆分完成后删除原笔记.
2. 优化上一步完成后的文件中的笔记内容, 使用markdown格式, 去除无关信息, 修复明显错误, 优化笔记结构, 如果语言不是中文翻译为地道中文.
3. 如果文件名不够清晰贴切, 重命名笔记文件为合适的文件名 `Flutter 如何设置 flutter analyze 为只关注 error 级别错误.md`
4. 按照上面的 `元数据模板` 设置笔记的元数据
5. 把笔记文件移动到适合的 `1.Area`这个一级分类下的二级分类下对应的三级分类中 (这个例子中最适合的是 `1.Area/Flutter/04.Method` ), 如果没有相关的二级分类, 创建对应的文件夹. 如果三级分类对应Roadmap文件不存在或没有有效内容, 使用 `Roadmap 生成提示词`生成对应的Roadmap
6. 使用obsidian双链的形式插入到对应Roadmap 中特定的知识点或模块下面. 如果找不到适合的知识点, 就在Roadmap的合适位置添加合适的知识点

## 注意事项

- 归类时的一级分类只能选 `1.Area`
- 只有三级分类有 `01.Roadmap/`等模板目录, 更深层次分类要复用三级分类中的模板目录
- 插入新双链到Roadmap索引文件中时, 不要修改已有的双链
- 一次性完成任务,不要停下来让用户确认
