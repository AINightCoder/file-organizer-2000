# 知识管理功能 - 快速开始指南

## 功能简介

File Organizer 2000 现在支持知识管理功能，可以自动将复杂的笔记拆分为原子化的独立笔记，每个笔记专注于单一知识点，便于管理和检索。

## 快速开始

### 1. 启用功能

在插件设置中找到"知识管理功能"区域，启用以下选项：

```
☑ 启用知识管理功能
☑ 启用原子化拆分
```

### 2. 配置参数（可选）

根据需要调整以下参数：

- **笔记最大长度**: 3000（推荐值）
- **笔记最小长度**: 100（推荐值）
- **拆分策略**: both（推荐）

### 3. 使用流程

#### 步骤1：准备测试笔记

创建一个包含多个知识点的笔记，例如：

```markdown
# Flutter开发笔记

## 什么是Flutter

Flutter是Google开发的跨平台UI框架...

## Flutter的优势

1. 热重载功能提高开发效率
2. 单一代码库支持多平台
3. 丰富的组件库...

## 如何安装Flutter

首先需要下载Flutter SDK...
```

#### 步骤2：放入Inbox

将笔记放入 `.fileorganizer2000/Inbox` 文件夹

#### 步骤3：自动处理

插件会自动：
1. 检测笔记包含多个知识点
2. 拆分为3个独立笔记：
   - `什么是Flutter.md`
   - `Flutter的优势.md`
   - `如何安装Flutter.md`
3. 删除原笔记
4. 对每个子笔记进行后续处理（分类、重命名、标签等）

### 4. 查看结果

在处理完成后，你会看到：
- 原笔记被删除
- 生成了3个独立的原子化笔记
- 每个笔记都有合适的文件名、标签和分类

## 常见使用场景

### 场景1：整理阅读笔记

**原笔记**：一篇长文章的读书笔记，包含多个章节要点

**拆分后**：每个章节的核心概念独立成笔记，便于后续关联和引用

### 场景2：会议记录拆分

**原笔记**：一次会议的完整记录，讨论了多个议题

**拆分后**：每个议题独立成笔记，方便后续跟进和管理

### 场景3：学习笔记整理

**原笔记**：一次学习session的笔记，涵盖多个知识点

**拆分后**：每个知识点独立成笔记，构建知识库更清晰

## 高级配置

### 自定义拆分提示词

在设置中可以自定义AI拆分的提示词，以适应特定的拆分需求：

```
分析以下笔记内容，按照单一知识点原则拆分成独立的原子化笔记。

要求：
1. 每个笔记专注一个核心概念或知识点
2. 保持每个笔记的语义完整性和独立性
3. 为每个笔记提供清晰的标题和知识点说明
4. 如果内容本身已经是单一知识点，返回原内容即可
```

### 拆分策略选择

- **atomic**: 仅按知识点拆分
- **length**: 仅按长度拆分（适合处理特别长的文档）
- **both**: 先按知识点拆分，然后检查长度（推荐）

## 注意事项

### ⚠️ 重要提示

1. **备份数据**
   - 在首次使用前，建议备份你的笔记库
   - 虽然有回滚机制，但建议保持谨慎

2. **AI模型选择**
   - 拆分质量依赖AI模型能力
   - 建议使用 GPT-4、Claude 3.5 或类似级别的模型
   - 可以在设置中配置使用的模型

3. **Token消耗**
   - 每次拆分会调用AI服务
   - 处理大量笔记会产生token消耗
   - 建议评估成本或使用本地模型（如Ollama）

4. **处理时间**
   - 拆分和递归处理需要时间
   - 建议从小批量笔记开始测试
   - 观察处理速度和质量

### 🎯 最佳实践

1. **从小批量开始**
   - 先用2-3个笔记测试功能
   - 观察拆分质量和处理结果
   - 根据需要调整配置

2. **合理设置长度**
   - minNoteLength 设为 100-200 字
   - maxNoteLength 设为 2000-3000 字
   - 避免过度拆分

3. **观察并优化**
   - 检查拆分后的笔记质量
   - 根据实际情况调整提示词
   - 优化拆分策略配置

4. **使用原子化原则**
   - 编写笔记时就考虑知识点划分
   - 使用清晰的标题和结构
   - 便于AI更好地识别和拆分

## 故障排查

### 问题1：笔记没有被拆分

**可能原因**：
- 功能未启用
- 笔记内容低于最小长度
- 笔记已经是单一知识点

**解决方法**：
1. 检查设置中是否启用了功能
2. 查看笔记长度是否超过 minNoteLength
3. 确认笔记确实包含多个知识点

### 问题2：拆分质量不理想

**可能原因**：
- AI模型能力不足
- 提示词不够清晰
- 笔记结构不清晰

**解决方法**：
1. 使用更强大的AI模型
2. 自定义拆分提示词
3. 优化笔记的标题和结构

### 问题3：处理速度慢

**可能原因**：
- 笔记太长
- 网络延迟
- AI服务响应慢

**解决方法**：
1. 调整 maxNoteLength 减小单次处理量
2. 使用本地AI模型（如Ollama）
3. 减少并发处理数量

### 问题4：拆分失败

**行为**：
- 系统会自动回退到不拆分模式
- 原笔记继续正常处理流程
- 不会影响其他功能

**处理**：
- 查看日志了解失败原因
- 调整配置后重试
- 必要时手动拆分笔记

## 常见问题 FAQ

### Q1: 拆分会删除原笔记吗？

**A**: 是的。拆分成功后会删除原笔记，但在删除前会先创建所有子笔记。如果创建失败，会回滚不会删除原笔记。

### Q2: 拆分后的笔记还会继续处理吗？

**A**: 是的。每个拆分后的子笔记都会走完整的处理流程，包括分类、重命名、格式化、标签推荐等。

### Q3: 可以禁用某个拆分策略吗？

**A**: 可以。在拆分策略中选择：
- `atomic`: 只用知识点拆分
- `length`: 只用长度拆分
- `both`: 两种都用（推荐）

### Q4: 拆分消耗多少token？

**A**: 取决于笔记长度和使用的模型。大致估算：
- 1000字笔记约消耗 2000-3000 tokens
- 包括输入和输出

### Q5: 可以使用本地模型吗？

**A**: 可以。支持 Ollama、LM Studio 等本地模型服务，在设置中配置即可。

### Q6: 拆分后的文件名是怎么定的？

**A**: AI会根据知识点内容生成清晰、描述性的文件名。后续还可以通过重命名功能进一步优化。

### Q7: 附件会怎么处理？

**A**: 如果原笔记有附件，第一个拆分笔记会继承该附件，其他笔记不会包含。

### Q8: 可以手动拆分吗？

**A**: 当前版本是自动拆分。如果不需要拆分，可以关闭功能，或者将笔记长度控制在 minNoteLength 以下。
