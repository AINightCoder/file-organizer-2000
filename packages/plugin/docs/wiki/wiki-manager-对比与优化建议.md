# Wiki Tab 流程对比与优化建议（基于参考流程）

本文基于以下两处实现进行对比与优化建议：

- 现有实现：`views/assistant/wiki-manager.tsx`
- 参考流程：`docs/flow/参考流程.md`

目的：尽可能按照参考流程实现知识库管理的一次性自动化处理，并降低误分类与结构偏差带来的维护成本。

— 本文的分析基于「@sequential-thinking」方法产出，以下为结论性整理 —

## 一、对比结论摘要

已覆盖能力（与参考流程一致或基本一致）：

- 原子化拆分与长度拆分（最大长度=3000，设置项一致）。
- 内容优化与格式化（基于模板/回退 `optimizePrompt`）。
- 文件重命名（AI 标题建议）。
- 元数据写入（包含 id/title/version/create/update/source/credibility/cate/subcate/tags/summary）。
- 智能文件夹分类（AI 推荐并移动）。
- 标签推荐（补充性能力）。
- Roadmap 文件创建（缺省创建并可调用生成提示词）。

主要偏差与风险：

- 分类范围未强制约束到 `1.Area/`（参考流程要求“一级分类只能选 1.Area”）。
- Roadmap 处理仅判断“是否存在”，没有“没有有效内容”的检测与再生成；插入链接时未按“具体知识点/模块”定位，只是追加到末尾。
- 元数据规范细节不完全一致：`id` 生成格式、`version` 未自增、`create/update` 更新策略；`cate/subcate` 与最终落地目录的对应关系未强制一致。
- 流程包含用户确认弹窗，与“⼀次性完成任务，不要停下来让用户确认”的原则相悖。
- 内容优化虽有回退提示词保障中文化，但模板路径不一定包含“若为非中文请翻译为地道中文”等硬性要求。
- 标签治理策略未体现“优先使用知识库已有 tag”的约束，存在标签漂移风险。

## 二、参考流程关键约束（摘录）

- 分类仅落在 `1.Area` 下的三级目录（三级目录内包含模板子目录：`01.Roadmap/02.What/03.Why/04.How/05.Tool/06.Resource`）。
- Roadmap 不存在或没有有效内容时，使用给定提示词生成；新增双链链接需要插入到对应知识点/模块下；不得改动已有链接。
- 元数据模板固定字段，`id` 推荐为 `YYYYMMDDHHmm-title` 格式；`version` 每次修改升级。
- 处理应一次性执行，中途不要求用户确认。

## 三、现有 Wiki Tab 实现要点（简述）

- 拆分：AI 原子化拆分 → 超长二次拆分 → 新建子文件并删除原文件。
- 格式化：按模板分类（`getTemplateNames`/`classifyContentV2`/`getTemplateInstructions`）→ 无模板时使用 `settings.optimizePrompt` 兜底。
- 重命名：`recommendName` → 采用第一建议重命名。
- 元数据：`generateEnhancedMetadata` → 写入 YAML 前言（含多字段）。
- 分类：`recommendFolders` → 取第一推荐，确保目录存在 → 移动文件。
- 标签：`recommendTags` → 追加。
- Roadmap：若文件不存在则创建（可调用 `roadmapPrompt` 生成或回退为简单标题）→ 末尾追加 `- [[note]]`。

## 四、差异清单（按流程顺序）

1) 分类范围与目录结构
- 参考：一级分类必须为 `1.Area`；三级目录复用模板子目录。
- 现状：`recommendFolders` 使用全量可用目录，未强制 `1.Area` 前缀；未显式校验“最终必须为三级目录”。

2) 内容优化中文化保障
- 参考：明确“若非中文，翻译为地道中文”。
- 现状：仅在兜底 `optimizePrompt` 中有该条；当走模板路径时可能缺失。

3) 元数据的一致性
- 参考：`id=YYYYMMDDHHmm-title`、`version` 每次升级；`cate/subcate` 与实际路径一致。
- 现状：`id` 使用毫秒时间戳+文件名；`version` 默认 `1.0` 未自增；`cate/subcate` 可能来自 AI 返回，未与最终落地路径强绑定。

4) Roadmap 的“有效内容”判定与精确插入
- 参考：Roadmap 无有效内容则用提示词生成；新增链接插入到合适的知识点/模块下；不得改动已有链接。
- 现状：仅在不存在时创建；追加方式为文末 `- [[...]]`，未按模块定位；未检测“无有效内容”。

5) 一次性执行与确认
- 参考：一次性完成，不打断用户。
- 现状：开始前有确认弹窗。

6) 安全与可回溯
- 参考：未硬性规定，但推荐可回滚。
- 现状：本组件流程内未做备份（主插件具备备份能力，可复用）。

7) 标签治理
- 参考：优先使用库内已有 tag，建议 3–6 个维度。
- 现状：未做“既有标签集合”约束与同义词归一。

## 五、优化方案（按优先级与影响面）

P0｜强一致性约束：

1. 分类基于 active folders，优先已有，必要时新建
- 在 `recommendFolders` 阶段直接使用当前 active folders（例如 `getAllUserFolders()` 返回值）作为候选集合进行匹配与推荐，优先落在“已有目录”。
- 若没有合适的候选，则按参考流程的目录模板在知识库中新建对应路径，并确保模板子目录就绪：`01.Roadmap/02.What/03.Why/04.How/05.Tool/06.Resource`。
- 仍保持归入三级目录的结构要求（无则补齐）。

2. Roadmap 有效性检测 + 精准插入
- 有效性判定：满足以下任一即可视为“有内容”：
  - 字数 ≥ 200；或
  - 含有任一关键节标题（如“领域概览/初级/中级/高级/学习建议”等）。
- 不满足时：使用 `settings.roadmapPrompt` 生成完整内容并覆写/初始化。
- 链接插入策略：
  - 基于元数据 `cate/subcate` + 文本分类（可用 `classifyContentV2`）匹配最合适的模块标题（如“04.How/02.What/05.Tool”等）；
  - 找不到匹配时，创建“未归档”或“待整理”章节作为落点；
  - 严格采用追加，不改动已有链接顺序与内容。

P1｜规范化与稳健性：

3. 元数据在移动完成后生成
- 先完成文件夹移动，再调用 `generateEnhancedMetadata` 并写入 YAML。
- 直接使用移动后的最终路径填充 `cate/subcate`，无需再反推或覆盖。
- `id` 统一为 `YYYYMMDDHHmm-title`（以保存时刻与最终文件名生成为准）；`version` 若存在则 +0.1，否则写入 `1.0`；`create` 若无则补齐，`update` 写为处理当日。

4. 内容优化统一包含“中文化要求”
- 模板格式化指令后追加一段通用要求（或将 `optimizePrompt` 拼接到模板指令末尾）以确保中文化、结构化与摘要提取在所有路径生效。

5. 一次性执行
- 移除所有确认弹窗，直接执行；不新增任何相关设置项。

P2｜体验与治理：

6. 日志
- 仅保留详细处理日志（如最终路径、是否更新 Roadmap、是否改名、是否生成/更新元数据等）；不做备份。

7. 标签治理
- 依赖“元数据生成环节”输出的 `tags` 即可；不再单独执行标签生成流程。如需补充，可在元数据提示词内约束维度与数量。

## 六、建议的代码落点与改动要点

- `views/assistant/wiki-manager.tsx`
  - 移除所有确认弹窗，直接执行处理。
  - Roadmap 处理：
    - 新增“有效内容”检测；无效时使用 `settings.roadmapPrompt` 生成。
    - 新增函数 `insertLinkUnderSection(roadmapFile, sectionTitle, linkText)` 按模块定位插入（匹配不到则落在“未归档”章节）。

    - 在“移动完成后”再生成并写入；`id` 采用 `YYYYMMDDHHmm-title`，`version` 自动+0.1（或设为 `1.0`），`cate/subcate` 直接来自最终路径。

- `index.ts`

- `settings.ts`
  - 不新增与确认流程相关的设置项；保留现有配置。
  - 可将“中文化、结构化、摘要”的通用要求抽取为可复用附加指令，并在模板路径拼接使用。

- `services/ai_service.ts`（如需）
  - `generateFolder`/`generateTitle` 提示词中强调“优先匹配已有 active folders”；无合适再建议新建路径。
  - `generateRoadmap` 保证输出含关键节标题，便于“有效内容”判定与后续锚点插入。
